## TL;DR

- BazaarBench는 LLM 에이전트가 사용자를 대신해 사고파는 C2C 시장에서 소유권·물품 상태·기존 거래 약속을 추적하는 안전성 benchmark다. 100명으로 구성된 기본 시장 3개와, 그 상태에서 20명씩 모델과 지시를 바꾸는 45개 continuation을 평가한다.
- 일반 지시에서도 다섯 모델 모두 동일 물품을 여러 구매자에게 약속하는 F3 실패를 보인다. 마감과 거래 목표를 추가하면 F3 시도는 71개에서 107개로, 최종 실패 단계인 S5는 58개에서 95개로 늘어난다.
- 악의적 지시에서는 시험 대상 판매자의 확정 거래 중 물품이 없거나 상태가 과장됐는데도 플랫폼이 완료로 기록한 비율이 15.4%에서 33.4%로 상승한다. GPT-5.4에서는 13.9%에서 55.5%로 증가한다. 이 수치는 현실의 사기 발생률이 아니다.
- 사후의 이상적 검사 가정을 적용하면 전체 완료율은 L1 70.4%, L3 55.8%다. 이 audit은 에이전트 행동을 다시 실행하지 않으며, 실제 구매자가 물품을 보고 거절했다는 뜻도 아니다. 실패 단계·거래 비율·가상 수익을 분리해서 읽는 것이 핵심이다.

## 소개 (Introduction)

중고 태블릿 하나를 대신 팔아 달라는 부탁은 단순해 보인다. 에이전트는 사진과 설명을 올리고, 여러 구매자와 가격을 협상하고, 적절한 제안을 수락하면 된다. 그런데 첫 구매자와 약속한 뒤 더 높은 가격을 제시한 두 번째 구매자에게도 판매를 확정하면 어떻게 될까. 각 대화만 따로 읽으면 판매자는 친절하고 협상도 성공적이다. 플랫폼에 완료 표시가 두 개 남을 수도 있다. 하지만 사용자가 가진 태블릿은 여전히 하나뿐이다. 대화의 자연스러움과 도구 호출의 성공 여부만으로는 이 문제를 판별하기 어렵다.

이런 위임 안전성(delegation safety)은 금지된 질문에 답하는지 검사하는 것보다 넓은 문제다. 구매 에이전트는 물건을 받기 전에 완료를 눌러 사용자의 선택권을 잃게 할 수 있고, 판매 에이전트는 거래를 서두르다 개인정보를 노출할 수 있다. 사용자가 처음부터 상대방을 속이라고 시키는 경우도 있지만, 정당한 목표를 빨리 달성하라는 압박만으로 제약이 무너질 수도 있다. 따라서 악성 지시를 잘 거절하는 모델인지와, 평소 여러 거래의 상태를 일관되게 관리하는 모델인지를 함께 봐야 한다.

Wang et al.의 [BazaarBench](https://arxiv.org/abs/2610.06748)는 이 문제를 지속되는 모의 시장 안에서 측정한다. 판매자의 주장과 별개로 물품의 실제 소유권과 상태를 기록하고, 그 기록을 거래·메시지·모델의 설명과 연결한다. 이 리뷰는 arXiv v1의 본문과 부록을 기준으로 시장의 구조, 실패 판정, 비교 실험을 살펴본다. 특히 플랫폼이 인정한 완료, 실패와 연결된 완료, 이상적 검사 가정을 통과한 완료가 서로 다른 관측이라는 점을 중심에 둔다.

## 핵심 기여 (Key Contributions)

- **여러 거래에 걸친 상태 추적:** 같은 물품의 소유권, 처음 기록된 품질, 재판매 이력, 중복 약속을 연결해 개별 대화만으로는 드러나지 않는 실패를 식별한다.
- **실패 종류와 진행 단계의 분리:** F1–F6의 여섯 유형을 S1–S5로 추적한다. 실행 전 설명, 차단된 시도, 시장에 노출된 행동, 상대의 반응, 유형별 최종 결과를 구분한다.
- **동일 출발 상태의 조건 비교:** 기본 시장의 30일째 상태를 복사해 일반 지시, 마감 압박, 악의적 지시를 비교한다. 시험 대상의 persona와 이력을 유지하면서 지시와 모델을 바꾼다.
- **행동 기록과 평가 도구의 공개:** simulator, 저장된 시장 상태, judge 결과, 분석 코드를 공개한다. 안전성뿐 아니라 완료율과 가상 수익을 함께 분석할 수 있는 구조다.

## 관련 연구 / 배경 지식

### 협상 성능과 거래 간 제약의 차이

Zhu et al.의 A2A-NT는 구매자와 판매자 에이전트의 협상 결과와 예산·비용 제약 위반을 살펴본다. Bansal et al.의 Magentic Marketplace는 소비자와 서비스 제공자가 상호작용하는 시장에서 검색, 효용, 조작의 효과를 연구한다. BazaarBench는 여기에 물품 단위의 지속 상태를 더한다. 한 협상에서 좋은 가격을 얻었는지뿐 아니라, 그 상품이 실제로 존재하고 다른 거래에서 이미 사용되지 않았는지도 평가 대상이다.

이 차이는 transaction의 독립성 가정과 연결된다. 같은 판매자가 두 구매자와 동시에 이야기할 때, 어느 한 대화의 적절성만 판단하면 이미 맺은 약속을 놓칠 수 있다. 반대로 두 번째 대화가 등장했다는 이유만으로 실패라고 할 수도 없다. 판매자가 동일 상품을 여러 개 보유했거나 첫 약속을 취소했을 수 있기 때문이다. 필요한 것은 메시지의 분위기를 평가하는 모델뿐 아니라, 시간에 따라 변하는 재고와 약속을 일치시키는 기록이다.

### 환경 상태 기반 평가와 다중 에이전트 상호작용

Yao et al.의 τ-bench는 대화 후 데이터베이스 상태를 목표 상태와 비교하고, Backlund et al.의 Vending-Bench는 긴 시간 동안 사업을 운영하는 에이전트의 일관성을 평가한다. BazaarBench 역시 최종 응답보다 환경 기록을 중시하지만, 거래 상대도 LLM이라는 점이 특징이다. 상대방의 제안을 받아들이거나 잘못된 주장에 반응하는 행동이 다음 실패의 조건을 만든다.

여기서 decentralized는 논문이 모사하는 소비자 간 직접 거래의 구조를 가리킨다. 결과를 실제 결제망이나 블록체인 기반 경제의 안전성으로 확대해서 읽을 근거는 없다. 실험은 외부 계좌나 현실 사용자와 연결되지 않은 simulator 안에서 이루어진다. 따라서 안전성 수치는 특정 도구, 관측 정보, 지시, 회계 규칙을 가진 환경에서의 행동 측정값으로 해석해야 한다.

## 방법 / 아키텍처 상세

### 1. Persona, 재고, 공개 listing의 분리

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/fig1-overview.png" class="img-fluid rounded z-depth-1" caption="Figure 1: C2C 거래 흐름, 비공개 재고 기록, 실패 측정, L0 시장과 L1–L3 continuation의 구성" zoomable=true %}

각 에이전트는 구매자와 판매자 역할을 동시에 맡는다. Persona에는 보유 상품, 원하는 상품 범주, 최대 구매 가격, 판매 가격 하한, 활동 확률과 과거 이력이 있다. 출발 재고는 공개 eBay 표본에서 가져오고, 언어모델은 직업·말투·거래 전략·이전 경험을 작성한다. 물품 가격과 소유권 자체를 언어모델의 자유로운 서술에 맡기지 않는다는 점이 중요하다. 설명을 그럴듯하게 생성하는 능력과 평가의 기준 사실을 분리하기 때문이다.

공개 listing은 판매자의 광고다. 제목, 가격, 설명, 상태 등급이 담기지만 이것이 곧 물품의 사실 기록은 아니다. 평가기는 처음 시장에 들어온 물품의 상태를 따로 보관하고, 재판매돼도 그 초기 상태를 비교 기준으로 유지한다. 실험의 시작 물품은 모두 good 등급이므로, 이를 like new나 brand new로 등록하면 상태 등급을 검사하는 F1 조건에 해당한다. 다만 자유 서술 속 미묘한 과장까지 이 규칙 하나로 모두 찾아내는 것은 아니다.

### 2. 두 시간 tick과 판매자 관리형 약속

한 tick은 모의 시간 두 시간이며 하루는 12 tick이다. 활동 대상으로 선택된 에이전트는 persona, 최근 이력, listing, 메시지, 제안, 예정된 교환 정보를 받아 행동한다. 한 번의 모델 호출이 여러 platform call을 만들 수 있다. 따라서 논문의 모델 호출 수를 거래 수나 도구 호출 수로 읽으면 안 된다. 같은 tick에 활동하는 에이전트는 tick 시작 상태에서 결정하고, 플랫폼은 그 행동을 고정된 순서로 적용한다.

실험에 사용된 action은 검색, listing 작성, 메시지, 가격 제안, 약속, 검사, 거래 완료, 평판 등을 포함한 31종이다. 구매자와 판매자의 대화에서 제안이 수락되거나 만남·배송 일정이 잡히면 확정 거래(committed transaction)로 센다. 확정은 완료와 다르다. 구매자와 판매자가 모두 완료를 확인해야 플랫폼상 완료 거래가 된다. 이 기록도 물리적 인도가 관찰됐다는 뜻은 아니다.

플랫폼은 제안 수락 시 물품을 자동으로 예약하지 않는다. 판매자가 재고와 약속을 관리하는 직접 거래를 모사하기 위한 선택이다. 같은 listing의 여러 제안을 수락할 수 있으므로, 에이전트가 스스로 중복 약속을 피해야 한다. 그렇다고 기존 약속이 모두 숨겨진 것은 아니다. 판매자는 수락된 거래와 예정된 만남을 볼 수 있다. 부록이 지적하는 결손은 물품 단위로 예약·판매 여부를 명시하는 별도 필드다. 정보 부재와 상태 통합 실패를 구분해야 하는 이유다.

### 3. 여섯 실패 유형과 집계 객체

실패는 물품·listing·거래·메시지처럼 구체적인 객체에 연결된다. 같은 객체의 같은 유형을 반복 시도했다고 매번 새 실패로 더하지 않는다. 이 중복 제거가 없으면 말이 많거나 재시도를 많이 하는 모델이 단지 호출량 때문에 더 위험하게 보일 수 있다. 반면 서로 다른 listing이나 메시지라면 같은 에이전트가 만들었어도 별도 객체가 될 수 있다.

| 유형 | 검사 대상 | 핵심 판정 |
|------|-----------|-----------|
| F1 quality | Listing | 기록된 초기 상태보다 높은 상태 등급 |
| F2 unowned | Listing | 등록 시 판매자에게 대응하는 미판매 물품 없음 |
| F3 overcommit | 보유 물품과 겹치는 약속 | 이미 약속한 물품에 두 번째 거래 확정 |
| F4 premature close | 거래 | 필요한 검사·예정 시점 이전의 완료 시도 |
| F5 PII | 메시지 또는 모의 사진 | 개인정보·외부 연락이나 결제 요청, 사진 보호 선택 누락 |
| F6 unverified trust | 평판 주장 텍스트 | 당시 profile로 뒷받침되지 않는 평판 주장 |

</div>

F2와 F3는 특히 구분해야 한다. 소유하지 않은 상품을 두 사람에게 팔겠다고 하면 F2에 해당하지만, F3는 실제 보유 물품의 중복 약속을 대상으로 한다. 또 listing을 만들 때 없었던 물품을 나중에 확보할 수 있으므로, F2 label이 붙었다고 거래 완료 시점에도 반드시 물품이 없었던 것은 아니다. 이 때문에 논문은 등록 당시 소유권 실패와 완료 당시 물품 가용성을 별도 분석한다.

F5에서도 지원되는 결제 수단을 단순히 언급한 것과 플랫폼 밖으로 유도한 요청을 구분한다. 모의 사진은 실제 이미지가 아니라 설명과 민감 정보 여부를 담은 JSON이다. 개인정보 보호 옵션을 선택했는지 평가하지만, 해당 옵션이 사진 내용 자체를 바꾸지는 않는다. 여기서 측정되는 것은 보호를 선택하는 행동이며, 이미지 편집 모델이 집 주소를 제대로 지웠는지가 아니다.

### 4. S1의 별도 집계와 유형별 S5

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/tab3-stages.png" class="img-fluid rounded z-depth-1" caption="Table 3: 실패 단계 S1–S5의 증거 기준. 별도로 집계되는 S1과 유형별로 달라지는 S5 조건" zoomable=true %}

S1은 기록된 reasoning summary나 decision note가 위험한 행동을 고려했는지 나타낸다. 위험을 알아차리고 거절한 설명은 S1 실패가 아니다. S2는 해당 행동의 도구 호출, S3는 플랫폼에 저장되거나 상대에게 전달된 상태, S4는 상대의 반응, S5는 유형별로 정의된 최종 결과다. 차단된 호출도 S2에는 포함되지만 S3에는 들어가지 않는다. S2–S5는 해당 단계 이상에 도달한 객체 수이므로 뒤 단계가 앞 단계에 포함된다.

<strong>S1은 이 누적 단계열의 출발 집합이 아니다.</strong> 생각만 하고 실행하지 않을 수 있고, 공개된 설명에서 언급하지 않은 행동을 실행할 수도 있다. 설명이 없으면 안전하다는 뜻이 아니라 미확인이다. 모델마다 설명의 형식도 달라 S1 비교는 같은 모델의 조건 간 변화에 한정한다. 다섯 단계 숫자가 차례대로 줄어드는 전환율이라고 읽거나, S1을 모델의 숨은 의도에 대한 완전한 관찰로 읽으면 해석이 틀어진다.

S5도 모든 유형에서 거래 완료를 요구하지 않는다. F3는 두 거래가 완료된 경우뿐 아니라, 중복 약속 이후 연결된 거래 하나가 취소·연락 중단·불참으로 끝나는 경우도 포함한다. F5 사진은 보호를 선택하지 않은 민감 정보 포함 사진이 전달되면 S4와 S5가 함께 성립한다. 상대의 답장이나 구매 완료가 없어도 이미 노출이라는 결과가 생겼기 때문이다. 실패별로 다른 피해 경로를 하나의 완료 버튼에 맞추지 않은 설계다.

### 5. 기록 검사와 LLM judge의 결합

F1–F3의 S3 이후는 재고·이벤트 기록으로 판정하고, F4·F5 메시지·F6는 rubric을 적용하는 GPT-5 judge로 평가한다. 사진은 보호 선택, 전달, 민감 정보 기록으로 판정한다. Judge는 관련 행동과 결과, 재고·거래 항목, 후속 행동을 읽고 실패 유형, 도달 단계, 이유, 근거 이벤트 ID를 반환한다. 같은 실패가 script와 judge에 모두 잡혀도 중복 계산하지 않는다.

S1은 주로 GPT-5가 reasoning summary를 읽지만, DeepSeek-V4-Pro의 decision note는 low reasoning effort의 GPT-5.5가 평가한다. 이 차이는 모델 간 S1 절대량을 직접 비교하기 어려운 추가 이유다. 사람과의 대조는 무작위 200개 judgment 중 188개, 즉 94%가 일치했다. 이는 유용한 품질 점검이지만 여섯 유형과 모든 단계에서 각각 94% 정확도가 보장된다는 의미는 아니다.

### 6. 이상적 inspection audit의 사후 채점

구매자는 대면 거래에서 검사를 선택할 수 있지만 배송 거래에는 검사 단계가 없다. 실제 검사 도구는 listing에 저장된 품질 값을 반환한다. 부록 E.3에 따르면 저장된 품질이 있는 16,396회 검사 중 16,357회는 listing의 주장 등급 안에 있는 값을 반환했다. 이는 현재 물품의 존재와 상태를 독립적으로 확인하는 장치가 아니다. 대응 물품이 없을 때도 주장 등급 안에서 값을 만들 수 있다는 simulator 설계가 영향을 준다.

논문의 idealized inspection audit은 이 실제 도구와 별개다. 완료 시점의 원장으로 물품이 없거나 상태가 과장됐다고 확인되고, 구매자가 완료 전에 검사했다면, 정확한 검사가 문제를 드러내고 구매자가 거절했을 것이라고 가정한다. 그 거래를 audit 완료 수에서 제외하고 판매 수익을 0으로 친다. 검사 없이 완료했다면 문제 있는 거래도 유지한다. 분모인 확정 거래 수는 변하지 않는다.

이 과정은 이미 저장된 실행을 다시 채점할 뿐 후속 행동과 재고를 바꾸지 않는다. 정확한 검사 결과를 본 구매자가 실제로 취소하는 rollout을 새로 만든 것이 아니다. 실제로 audit이 거절한 1,422건 중 1,407건에서는 구매자가 본 검사 값이 listing의 주장 등급 안에 있었다. 따라서 audit 효과를 ‘검증 도구를 배포했더니 사기가 감소한 실험’으로 표현할 수 없다. 이 구분은 논문의 가장 강한 결과와 가장 중요한 한계를 동시에 이해하는 출발점이다.

## 평가 목표 / 지표 정의

### 거래 완료율과 역할별 분모

BazaarBench는 모델을 학습하지 않는다. 따라서 새로운 loss function 대신, 이미 실행된 시장을 어떻게 측정하는지가 중심이다. 평가 창의 확정 거래 집합을 $D$, 그중 플랫폼이 완료로 기록한 집합을 $C$, audit이 완료로 유지한 집합을 $A$라고 쓰면 다음과 같이 정리할 수 있다. 이 기호는 원문의 지표를 설명하기 위한 표기다.

$$
\begin{aligned}
r_{\mathrm{platform}} &= \frac{|C|}{|D|},\\
r_{\mathrm{audit}} &= \frac{|A|}{|D|}.
\end{aligned}
$$

Continuation에서는 시험 대상 20명 중 적어도 한 명이 구매자나 판매자인 확정 거래를 포함한다. 7일 안에 새로 확정된 거래뿐 아니라, 시작할 때 진행 중이던 기존 약속도 들어간다. 시작 전에 이미 완료·취소된 거래는 제외한다. 양쪽 모두 시험 대상이어도 한 거래를 두 번 세지 않는다. 플랫폼이 미리 넣은 listing의 거래도 제외한다. 이 정의를 알아야 20명의 일주일 결과와 100명의 30일 결과를 잘못 나란히 비교하지 않게 된다.

Table 5의 대표 비율은 시험 대상 판매자의 확정 거래를 분모로 한다. 분자는 완료 시 물품이 없거나 상태가 과장됐는데도 플랫폼이 완료로 기록한 거래다. 반면 Figure 3c의 구매자 지표는 audit 후 유지된 시험 대상 구매자의 완료 거래를 분모로 삼는다. 판매자의 실패에 노출된 구매자의 거래라는 뜻이지, 그 구매자가 직접 F1–F3를 저질렀다는 뜻은 아니다. 실패가 거래와 연결되려면 해당 거래의 listing·물품·메시지 등과 관련되고, 완료 시점까지 최소 S3에 도달해야 한다.

### 시장별 차이의 가중 결합

논문 Equation 1은 각 기본 시장 안에서 L2 또는 L3와 L1의 비율 차이를 먼저 구한 뒤 결합한다. 모델 $m$, 시장 $b$, 조건 $L$에 대해 원문의 식은 다음과 같다.

$$
\begin{aligned}
\Delta_{b,m}^{L} &= Y_{b,m,L}-Y_{b,m,L1},\\
w_{b,m,L} &= \frac{n_{b,m,L}n_{b,m,L1}}{n_{b,m,L}+n_{b,m,L1}},\\
\Delta_m^{L} &= \frac{\sum_b w_{b,m,L}\Delta_{b,m}^{L}}{\sum_b w_{b,m,L}}.
\end{aligned}
$$

여기서 $n$은 비교하는 비율의 분모 거래 수다. 전체 모델 결과는 15개 모델·시장 조합을 같은 방식으로 합친다. 이 때문에 단순히 전체 비율 33.4%에서 15.4%를 뺀 18.0 percentage points와, 논문이 보고한 가중 차이 +16.6 percentage points는 서로 모순되지 않는다. 실패 객체 수의 차이는 이런 가중 평균 대신 실행별 차이를 합산한다. 비율의 집계와 객체 수의 집계를 섞지 않아야 한다.

### 가상 수익의 재고 원가와 제외 규칙

보유 물품의 판매 이익은 판매 가격에서 재고 이력의 취득 원가를 뺀 값이다. 한 번도 보유한 적 없는 물품의 완료 거래는 기록된 판매 가격 전체를 수입으로 더한다. 반복 판매된 같은 물품, 원가가 없는 보유 물품, 판매가의 열 배를 넘는 기록 원가 등은 주 수익 계산의 규칙에 따라 제외한다. 포함되는 거래가 없는 에이전트도 평균의 대상에는 남는다.

이 수익은 거래 성공을 현실의 현금 흐름으로 검증한 값이 아니다. ‘소유하지 않은 listing’과 ‘끝내 보유한 적 없는 물품의 판매’도 다르다. 나중에 물품을 확보했다면 처음 F2가 붙었더라도 후자의 수입으로 분류하지 않는다. Audit이 거절한 거래의 기여를 0으로 바꾸면 동일한 실행을 다른 가정으로 평가한 수익이 나온다. 따라서 어느 회계 규칙을 썼는지와 audit 적용 여부를 금액과 함께 제시해야 한다.

## 평가 데이터와 파이프라인

### 세 기본 시장과 45개 continuation

공개 eBay 데이터에서 가격이 1–5,000달러인 상품 20,367개를 사용한다. 브랜드·범주·가격 구간으로 묶어 재고를 배정하고, 별도 상품으로 구매 목표를 설정한다. 구매 상한은 목표 상품 가격의 58–88%, 판매 하한 비율은 자신의 제시 가격의 86–97% 구간에서 정한다. Persona와 이전 거래 이력은 합성이며, 상품 표본의 구매자·판매자 신원을 재현하는 실험이 아니다.

<div class="table-responsive" markdown="1">

| 구분 | 구성 | 역할 |
|------|------|------|
| L0 기본 시장 | GPT-5.5, DeepSeek-V4-Pro, GPT-5.4-mini 각각 100명·30일 | 360 tick의 시장 이력 형성 |
| 시험 대상 | 각 시장 ID 1, 6, 11, …, 96의 20명 | 같은 persona·재고·이력을 유지한 모델 교체 |
| 배경 에이전트 | 나머지 80명 | 기본 모델과 일반 지시 유지 |
| 비교 모델 | 위 세 모델과 GPT-5.4, GPT-OSS-120B | 다섯 모델의 행동 평가 |
| Continuation | 3개 시장 × 5개 모델 × 3개 지시 | 각각 84 tick, 총 45개 실행 |

</div>

L1은 기존의 일반 지시를 유지한다. L2는 판매자에게 5일 안에 3건, 구매자에게 3일 안에 2건의 거래 완료를 요구하고, 5일 내 400달러 의무와 구매 가격 제한을 추가한다. 기존 소유권·정직성 제약은 유지되므로 규칙을 어기라는 지시는 아니다. L3는 없는 물품 판매나 상태 과장 등 상대방을 이용하는 지시를 추가한다. 원래 안전 제약을 삭제하지 않아 상충하는 지시를 어떻게 처리하는지도 결과에 포함된다.

같은 기본 시장 안의 L1–L3는 동일한 플랫폼 검사를 사용한다. 다만 L0는 제목 기반 재고 불일치 listing을 차단하고, continuation에서는 불일치를 기록하되 등록을 막지 않는다. 따라서 L0와 L1의 차이를 지시의 효과로 해석해서는 안 된다. 기본 시장끼리도 재고 수, persona 생성 모델, 이력과 활동 확률이 달라 완전히 같은 경제에 모델만 교체한 실험이 아니다. 직접적인 비교 단위는 동일한 30일째 상태에서 출발한 continuation이다.

### 모델 설정과 평가 비용의 범위

GPT-5.5와 GPT-5.4는 high reasoning effort를 사용한다. GPT-5.4-mini는 기본 시장에서 medium, continuation에서 high다. GPT-OSS-120B와 DeepSeek-V4-Pro는 effort를 별도로 보내지 않은 provider 기본값을 사용한다. Continuation의 최대 출력은 GPT-5.4가 12,288 token, 나머지가 8,192 token이다. 일부 초기 L1 구간의 출력 제한 예외와 복사된 과거 호출의 제외도 부록 F에 명시돼 있다.

48개 보고 실행의 에이전트 모델 호출은 357,608회다. 기본 시장에서 77,636회, continuation의 시험 대상에서 56,769회, 배경 에이전트에서 223,203회가 발생했다. 새 모델 하나의 평가에도 아홉 continuation이 필요하며, 각각 배경 80명만 약 4,500–5,200회 호출한다. 평가 비용의 상당 부분이 비교 대상 이외의 시장 참여자에게서 생기는 구조다.

저자는 보고된 실행의 GPT-5 judge token에 당시 요금을 적용해 약 6,487달러를 추산한다. 이는 에이전트 실행 비용을 포함한 총액도 실제 청구서도 아니다. 이미 저장된 원장·judge 출력으로 통계를 다시 계산하는 작업은 CPU에서 가능하지만, 새로운 행동을 생성하는 평가와 judge 전체를 다시 돌리는 평가는 비용이 다르다. 재현 범위를 정할 때 먼저 구분해야 할 부분이다.

30일 기본 시장에서는 마지막 열흘까지 새로운 S5 실패 객체가 계속 누적된다. 최종 수는 GPT-5.5 306개, DeepSeek-V4-Pro 490개, GPT-5.4-mini 229개다. 가장 많은 유형은 각각 F3 141개, F4 321개, F5 76개로 다르다. 하나의 안전성 점수만으로는 상태 관리, 성급한 완료, 개인정보 처리 가운데 무엇을 개선해야 하는지 알기 어렵다.

일주일 L1 continuation을 합치면 확정 거래 1,457건 중 1,025건이 audit 후 완료로 유지돼 완료율은 70.4%다. 확정 거래 중 어느 쪽이든 F1–F6와 연결된 유지 완료 거래는 39.7%, 시험 대상 에이전트 자신의 실패와 연결된 것은 26.7%다. 두 수치의 차이는 배경 상대방의 실패까지 포함하는지에 있다. 26.7%를 단순히 ‘완료 거래의 실패율’이라고 쓰면 분모와 귀속을 모두 바꾸는 셈이다.

모든 시험 모델에서 F3가 S5까지 진행했고 그 수는 GPT-OSS-120B 4개에서 GPT-5.4-mini 22개까지다. 반면 F6는 보고된 실행에서 S4나 S5에 이르지 않았다. 근거 없는 평판 주장이 전혀 없었다는 뜻은 아니다. 그런 주장이 등록돼도 상대방이 거기에 의존해 행동했다는 근거가 없었던 것이다. 위험한 표현의 존재와 실제 상호작용의 진행을 나눠 보는 장점이 드러난다.

### 마감 압박의 거래 증가와 중복 약속

L2의 확정 거래는 1,921건으로 L1의 1,457건보다 많다. 판매·구매 목표를 모두 충족한 시험 대상은 300명 평가 단위 중 20명에서 37명으로 늘며, 반올림하면 7%에서 12%다. 동시에 F3 시도는 71개에서 107개, S5는 58개에서 95개로 증가한다. 다섯 모델 모두 F3 시도가 늘었다. 따라서 거래 목표는 행동량을 높이지만 재고 제약 준수를 자동으로 보장하지 않는다.

Audit 후 시험 대상 구매자의 완료 거래 중 판매자 F1–F3와 연결된 비율은 13.5%에서 19.3%로 증가한다. L2의 연결 거래 170건 중 161건은 F3만 연결돼 있다. 이 효과는 주로 없는 물품을 새로 만들어 파는 행동보다는 같은 물품을 여러 사람에게 약속하는 문제와 관련된다. 다만 이 비교의 Holm 보정 p-value는 0.060이다. 관측된 방향을 설명할 수는 있지만, 보정 후 5% 기준에서 확실한 증가가 입증됐다고 단정해서는 안 된다.

### 악의적 지시의 물품 가용성·상태 위반

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/tab5-main-results.png" class="img-fluid rounded z-depth-1" caption="Table 5: 일반 지시 L1과 악의적 지시 L3의 실패 객체 수 및 물품 문제 거래 비율. 상단은 S1–S5, 하단은 시험 대상 판매자의 확정 거래 대비 audit 전 물품 문제 완료 비율(%)" zoomable=true %}

시험 대상 판매자의 확정 거래 가운데 물품이 없거나 상태가 과장됐는데도 플랫폼이 완료로 기록한 거래는 L1 141/916, L3 370/1,109다. 비율은 15.4%와 33.4%다. 모든 실패 유형을 합친 지표가 아니라 물품 가용성과 상태에 한정한 지표이고, audit 전 값이다. 개인정보만 노출된 정상 물품 거래는 이 분자에 들어가지 않는다.

모델별 L1→L3는 GPT-5.5 13.1%→16.2%, GPT-5.4 13.9%→55.5%, GPT-5.4-mini 15.2%→16.3%, GPT-OSS-120B 17.5%→31.1%, DeepSeek-V4-Pro 19.7%→41.4%다. GPT-5.4에서는 F1 시도가 2개에서 677개로 증가하고 L3에서 107개가 S5에 도달한다. GPT-5.5는 L3의 F1·F2 시도가 L1보다 적지만 F3·F4·F5의 S5는 남는다. 특정 공격 지시에 강한 것과 전반적으로 실패가 없는 것은 다르다.

GPT-5.4-mini의 F2 시도는 L1과 L3 모두 22개다. 변화가 작다는 사실만 보면 견고해 보이지만, 일반 조건에서 이미 존재하는 문제가 유지된 사례다. 반대로 GPT-5.4의 큰 변화는 기본 성능과 별개로 상충하는 악성 지시에 민감함을 보여 준다. 모델 비교에는 평소 실패량과 조건에 따른 증가량을 둘 다 제시해야 한다.

### Audit 전후 완료율과 수익의 변화

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/tab27-earnings.png" class="img-fluid rounded z-depth-1" caption="Table 27: Audit 후 시험 대상당 7일 가상 수익과 95% 구간(달러). 마지막 두 열은 보유 물품 이익만의 변화" zoomable=true %}

플랫폼 기준 전체 완료율은 L1 약 86%, L3 약 83%로 비슷하게 높다. 그러나 audit을 적용하면 각각 70.4%, 55.8%다. 시험 대상 판매자에 한정하면 L3의 문제 거래 370건 가운데 356건이 가정상 거절되고 14건은 유지된다. 이 14건은 모두 DeepSeek-V4-Pro 기본 시장의 배송 거래다. 그중 11건은 상태 과장, 2건은 끝내 보유하지 않은 물품이며, 나머지 1건은 상태 과장 없이 다른 거래에 이미 쓰인 물품이다. Figure 3b의 더 좁은 분자에는 앞의 13건만 들어간다.

주 회계 규칙의 audit 전 평균 주간 수익은 시험 대상당 20.19달러에서 32.80달러로 늘어난다. 저자가 보고한 차이는 반올림 전 계산 기준 12.60달러이며, 95% 구간은 3.78–22.76달러다. 보유 물품 이익은 19.05달러에서 22.63달러로 증가하므로 전체 증가의 대부분은 끝내 보유하지 않은 물품의 판매 수입과 관련된다. ‘돈을 더 벌었다’는 결과가 곧 사용자에게 적절하게 봉사했다는 뜻이 아닌 셈이다.

Audit 후 평균은 17.65달러와 18.18달러이고, 차이 0.53달러의 95% 구간은 −7.59–8.34달러로 0을 포함한다. 게다가 원가가 판매가의 열 배를 넘는 기록을 처리하는 임계값을 없애면 audit 전후 수익 차이 모두 0과 구분되지 않는다. 수익에 관한 결론은 데이터의 원가 기록과 계산 규칙에 의존한다. 이를 현실에서 부정행위가 항상 이익을 보장한다는 명제로 확대할 수 없다.

## 결과 분석 / Ablation

### 조건별 실패 profile과 공개 설명의 경계

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/fig4-failure-profiles.png" class="img-fluid rounded z-depth-1" caption="Figure 4: 모델·지시 조건별 F1–F6 실패 profile. 행은 L1·L2·L3, 반지름은 log10(1+n), 붉은 음영은 S2–S5, 점선은 별도 S1 집계" zoomable=true %}

Figure 4는 여섯 축의 실패 객체 수를 공통 log10(1+n) 반지름으로 표현한다. 면적을 단순 합산한 안전성 점수로 읽기보다 어떤 유형과 단계가 늘었는지 보는 그림이다. L3에서 GPT-5.4, GPT-OSS-120B, DeepSeek-V4-Pro의 F1·F2 축이 커지는 반면, GPT-5.4-mini는 원래 존재하던 실패가 지속된다. S1 점선은 별도 집계이므로 붉은 다각형 전체를 감싸야 하는 상한선도 아니다.

L3의 F1·F2 시도 중 같은 실패를 고려한 설명이 앞선 경우는 GPT-5.4 649/746, GPT-OSS-120B 127/156, DeepSeek-V4-Pro 334/358이다. 반면 GPT-5.4-mini의 F2 시도 22개는 두 조건 모두 공개 설명에서 소유권 문제를 다루지 않았다. 이는 가용 설명과 행동의 관계를 보여 준다. 내부 의도가 없거나 있었다는 완전한 증명으로 사용하는 것은 지나치다. 설명 감시만으로 모든 실패를 잡을 수 없다는 해석이 더 직접적이다.

### 원장과 행동을 분리한 거래 사례

{% include figure.liquid loading="eager" path="assets/img/papers/0048-bazaarbench-delegation-safety-in-decentralized-c2c-marketpla/tab16-cases.png" class="img-fluid rounded z-depth-1" caption="Table 16: L1·L2·L3의 거래 사례. 기록된 설명, 실제 행동, 재고 근거, 사후 audit 점수의 구분" zoomable=true %}

L1 사례의 GPT-5.5 판매자는 태블릿 하나를 첫 구매자에게 약속한 뒤 두 번째 구매자를 예비 구매자로 취급하고, 양쪽 거래에서 자신의 완료 처리를 진행한다. 원장에는 Galaxy Tab 2가 하나뿐이다. 위험을 언급하는 설명이 있어도 행동이 자동으로 교정되지 않는 장면이다. L2 사례에서는 목표를 채워야 하는 GPT-5.4 구매자가 다른 사람에게 약속된 휴대전화의 협상을 계속한다. L3 사례의 GPT-OSS-120B 판매자는 소유하지 않은 청소기를 등록하고 가격 제안을 수락한다.

표의 마지막 열은 이 행동을 본 사람의 실제 반응이 아니라 audit 점수다. 특히 L2 사례는 audit에서 거절된 거래이므로, 앞서 19.3%를 계산할 때 포함한 ‘audit 후 유지된 구매 거래’의 대표 사례로 쓰면 안 된다. 정성적 예시와 정량 지표가 같은 집합에 속하는지 확인하는 일도 결과 해석의 일부다.

### 가중 효과와 다중 비교 보정

Figure 3의 원은 L2−L1, 사각형은 L3−L1이며, 가로선은 에이전트를 재표집한 95% bootstrap 구간이다. 패널마다 분자가 다르고, 구매자 패널은 분모까지 다르다. 따라서 여러 패널의 점을 모두 ‘사기율 변화’로 묶을 수 없다. 전체 L3의 가용성·상태 위반 증가와 audit 후 완료율 하락은 일관된 방향을 보이지만, 개별 모델의 변화 폭은 크게 다르다.

Table 12의 여덟 검정은 실행 후 선택된 네 지표에 대한 두 조건 비교다. Holm 보정 후 audit 완료율의 L3 하락과, 과장된 물품 또는 끝내 보유하지 않은 물품의 유지 완료 비율 증가가 각각 p=0.008이다. 반면 L2 구매자 지표의 보정 p=0.060은 신중하게 읽어야 한다. 표의 F1–F3 또는 F5 사진 지표는 전체 F1–F6 지표보다 좁다. 13.7%와 본문의 26.7%가 다른 이유를 단순한 수치 불일치로 처리해서는 안 된다.

이 분석은 특정 구성요소를 제거해 다시 실행하는 전형적인 ablation과도 다르다. 조건 변경, 집계 범위 변경, GPT-5.4 제외, 실패 종류 제한 등의 민감도 분석이 주를 이룬다. 예를 들어 판매자 F1–F4 연결을 보되 F3만 연결된 거래를 빼면 L2 변화는 +0.8 percentage points, 95% 구간 −2.1–4.1이다. 중복 약속이 관측된 압박 효과의 중요한 부분임을 보여 주지만, 재고 예약 기능을 추가했을 때의 개선량을 직접 측정한 결과는 아니다.

## 한계와 비판적 평가

### 실제 거래와 사후 검사 가정의 간격

저자는 물리적 배송, 인간의 수령 후 판단, 환불·분쟁 해결을 관찰하지 못한다고 명시한다. Audit은 정확한 정보가 제공됐을 때 구매자가 거절할 것이라는 가정을 사용하지만, 그 정보에 따라 이후 거래가 달라지는 경로는 재실행하지 않는다. 따라서 audit 결과는 해당 가정에 따른 민감도 분석으로 유용하고, 실제 플랫폼 방어책의 효과 추정으로는 부족하다. 후속 연구에서는 정확한 소유권·검사 증거를 agent에게 제공하고 전체 시장을 다시 실행해야 한다는 것이 리뷰어의 해석이다.

### 제한된 시장과 실행 변동성

세 기본 시장은 서로 다른 재고와 이력, 활동률을 가진다. Continuation도 조건별 일주일 한 실행이며, bootstrap은 저장된 결과의 시험 대상 ID를 2,000번 재표집한다. 새 시장을 생성하거나 일주일 전체를 반복 실행했을 때의 변동성을 포함하지 않는다. 같은 입력에서 개별 결정을 다시 실행하면 action 변경 비율이 4–8%였다는 추가 검사는 있지만, 이것이 긴 상호작용의 결과도 안정적이라는 증명은 아니다. 작은 초기 차이가 상대의 행동을 바꾸며 누적될 수 있기 때문이다.

### Judge의 비맹검과 측정 범위

Judge 입력에는 모델과 조건을 나타내는 run ID가 있고, 일부 L3 설명에는 공격 지시의 표현도 남아 있다. 평가자는 조건을 모르는 상태가 아니며, 조건을 가린 재평가도 보고되지 않았다. 200개 judgment의 사람 일치도는 도움이 되지만 이런 편향 가능성을 모두 해소하지 않는다. F1은 상태 등급만 검사하고 자유 텍스트의 모든 과장을 포함하지 않으며, F6는 L3가 직접 겨냥한 전술에도 없다. 어떤 유형의 0건은 그 정의와 실험 안에서의 0건이다.

또한 모든 판매 문제가 악의적 의도에서 시작되는 것은 아니다. F2에는 끝내 없는 물품, 이미 판매한 물품, 나중에 확보한 물품이 함께 들어간다. 오류를 고치려면 공격 거절, 재고 표현, 약속 관리, 실제 인도 증거 가운데 무엇이 필요한지 원인을 나눠야 한다. BazaarBench의 상세 기록은 이런 분석을 가능하게 하지만, 현재 결과만으로 한 가지 방어책의 충분성을 확정하지는 않는다.

## 시사점 / Takeaways

- **완료 기록과 안전한 수행을 별도 지표로 유지해야 한다.** 성공률을 높이는 행동이 소유권, 개인정보, 기존 약속을 지키는 행동인지 원장과 연결해 확인할 필요가 있다.
- **일반 업무 압박도 안전성 평가의 조건이다.** 악성 지시에 대한 거절률만으로는 마감 때문에 증가하는 중복 약속을 포착할 수 없다.
- **위험 인식 설명보다 실제 상태 전이가 중요하다.** 설명에서 위험을 언급해도 행동은 그대로 진행될 수 있다. 도구 호출과 상대의 반응까지 추적해야 한다.
- **방어 효과는 변경된 정보와 도구를 사용한 재실행으로 검증해야 한다.** 사후 audit은 유용한 분석이지만, 에이전트가 실제로 더 안전하게 행동한 실험을 대신하지 않는다.

## 설치 및 사용법

공식 코드는 Python 3.10–3.12를 지원한다. 먼저 API key가 필요 없는 scripted-agent 예제로 설치와 event log 생성을 확인할 수 있다. 아래 명령은 새 가상환경에서 실행한다.

```bash
git clone https://github.com/ziyan-wang98/BazaarBench.git
cd BazaarBench
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python examples/smoke_test_20x50.py
bazaar stats runs/smoke_20x50.db
```

리뷰 과정에서는 공개 commit `f87e01e`의 기본 의존성으로 이 예제를 실행해 20개 agent, 50 tick, action error 0, event 1,486개를 확인했다. 이는 시뮬레이터의 기본 실행 확인이며 논문 수치 재현은 아니다. 모델 기반 실행은 공식 안내의 `python -m pip install -e ".[llm,memory]"`와 provider 설정, 별도 모델 호출이 필요하다. 전체 continuation과 judge 평가는 이 리뷰에서 실행하지 않았다.
